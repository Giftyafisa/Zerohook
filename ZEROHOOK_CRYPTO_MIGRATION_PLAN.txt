REQUIRED IMPROVEMENTS:

4.1 — MULTI-SOURCE DETECTION WATERFALL
────────────────────────────────────────
  The system should try each source in order, stopping at the first confident result.
  This is called a "waterfall" or "confidence chain":

  SOURCE 1: User's Saved Preference (highest priority if logged in)
    → User.profile_data.location.country (saved in MongoDB)
    → Confidence: DEFINITIVE — user explicitly set this
    → When to use: Always check this first for logged-in users

  SOURCE 2: Browser Geolocation API (GPS-level accuracy, needs permission)
    → navigator.geolocation.getCurrentPosition()
    → Returns lat/lng → Reverse geocode to country code via:
      GET https://api.ipgeolocation.io/timezone?apiKey=KEY&lat=LAT&long=LNG
    → Confidence: VERY HIGH — physical GPS coordinates
    → When to use: When user grants location permission (ask on signup/wallet page)

  SOURCE 3: Browser Language + Timezone Correlation
    → navigator.language = "yo-NG", "ha-NG", "sw-KE", "zu-ZA", "tw-GH"
    → Intl.DateTimeFormat().resolvedOptions().timeZone = "Africa/Lagos", "Africa/Nairobi"
    → Correlation table maps language+timezone to country code
    → Confidence: HIGH — hard to fake both together

  SOURCE 4: IP Geolocation (ipgeolocation.io)
    → Already implemented in IPGeolocation.js
    → Improvements needed:
      - Add security check (VPN/proxy detection) via &include=security parameter
      - If VPN detected: flag user, do NOT auto-set currency, ask user to confirm
      - Add 3 fallback IP geo providers (see below)
    → Confidence: MEDIUM-HIGH for real IPs, LOW for VPN users

  SOURCE 5: Phone Number Country Code (for registered users)
    → Already implemented in CountryManager.js → detectCountryFromPhone()
    → Improvement: Run this on registration completion automatically
    → Confidence: HIGH

  SOURCE 6: Payment History Pattern
    → If user has previous transactions in NGN → they are likely Nigeria
    → Transaction.find({ user_id }).distinct('currency') 
    → Map currency to country as a hint
    → Confidence: MEDIUM

  SOURCE 7: Default Fallback
    → Nigeria (NG) with explicit "Please confirm your country" prompt shown
    → Never silently assume — always inform user when using fallback
    → Confidence: LOW — user prompted to confirm

4.2 — FALLBACK IP GEO PROVIDERS (resilience)
──────────────────────────────────────────────
  If ipgeolocation.io fails, try in order:
  1. ipgeolocation.io          (primary — already integrated)
  2. ip-api.com/json/{ip}      (free, no key needed, 45 req/min)
  3. ipwhois.app/json/{ip}     (free, no key needed)
  4. geoip2.maxmind.com        (paid but very accurate)

  Implementation: IPGeolocation.js should have a lookupWithFallback(ip) method
  that wraps all providers and returns the first successful result.

4.3 — VPN / PROXY DETECTION
──────────────────────────────────
  The existing IPGeolocation.js already has getSecurityInfo() which checks:
    - is_vpn, is_proxy, is_tor, is_bot, is_spam
  
  NEW BEHAVIOR when VPN detected:
    - Do NOT auto-assign country/currency
    - Show banner: "We detected a VPN. Please select your country manually."
    - Store vpn_detected: true in session
    - Do NOT restrict access — just ask for manual country selection
    - Allow user to proceed after selection

4.4 — LOCATION DATA CACHING STRATEGY
───────────────────────────────────────
  Current: Simple in-memory Map with 24-hour expiry
  Needed:
    Level 1: Request-level cache (per session, instant)
    Level 2: Memory cache — IP → location (24h TTL, max 10,000 entries)
    Level 3: MongoDB cache — store UserLocation document per userId

        confidence, lastUpdated, manualOverride }
    Level 4: Revalidation — Background job re-checks IP every 7 days

SECTION 5 — ADVANCED CURRENCY & LIVE CONVERSION SYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

CONCEPT: Every price on the platform has ONE source of truth (USD), but is
DISPLAYED to the user in their LOCAL FIAT CURRENCY. When they pay, the system
converts to whatever crypto they choose, at the LIVE RATE at that moment.

5.1 — PRICING MODEL
──────────────────────
  Service providers set their prices in: USD (global baseline)
  The system stores all prices in: USD
  The system displays prices in: User's detected local currency
  The system charges in: User's chosen cryptocurrency

  Example:
    Provider lists service at: $50 USD
    Nigerian user sees:         ₦82,500 NGN  (live rate)
    Kenyan user sees:           KSh 6,450     (live rate)
    UK user sees:               £39.20        (live rate)
    User pays in:               USDT 50.00    (stablecoin, 1:1 with USD)
    User pays in:               0.000512 BTC  (live BTC/USD rate)

5.2 — LIVE RATE PROVIDERS (3-tier with fallback)
──────────────────────────────────────────────────
  FIAT rates (NGN, GHS, KES, ZAR, EUR, GBP, etc.):
    Primary:   ExchangeRate-API   https://v6.exchangerate-api.com/v6/{KEY}/latest/USD
               Free tier: 1,500 requests/month | Paid: unlimited
               Response: { "conversion_rates": { "NGN": 1650, "GHS": 15.2, ... } }

    Fallback1: Open Exchange Rates  https://openexchangerates.org/api/latest.json?app_id={KEY}
               Free tier: 1,000 requests/month

    Fallback2: Frankfurter API     https://api.frankfurter.app/latest?from=USD
               Completely FREE, no key needed, no rate limit
               Limited to major currencies (no NGN/GHS but covers EUR/GBP/JPY etc.)

  CRYPTO rates (BTC, ETH, USDT, USDC, BNB, SOL, LTC):
    Primary:   CoinGecko API   https://api.coingecko.com/api/v3/simple/price

               GET /simple/price?ids=bitcoin,ethereum,tether,...&vs_currencies=usd

    Fallback1: NOWPayments estimate endpoint (already integrated)
               GET https://api.nowpayments.io/v1/estimate?amount=1&currency_from=usd&currency_to=btc

    Fallback2: Binance public ticker (no key needed)

5.4 — CACHING ARCHITECTURE FOR RATES
───────────────────────────────────────
  Fiat rates cache TTL:   15 minutes  (fiat doesn't move fast)
  Crypto rates cache TTL: 60 seconds  (crypto moves fast — IMPORTANT)
  Rate data stored in:    Memory cache (Map) + optionally Redis if available

  Rate staleness indicator:
    → Every displayed price includes "Rate from X seconds ago"
    → If rate is >5 min old for crypto → show warning: "Rate may be outdated — refresh"
    → Rates auto-refresh in browser every 30 seconds on wallet/checkout pages

5.5 — RATE LOCK AT INVOICE CREATION
──────────────────────────────────────
  When a user initiates a payment:
    - The exact crypto amount is calculated at that moment
    - This rate is LOCKED for 20 minutes (NOWPayments invoice expiry)
    - After 20 min the invoice expires and a new one must be created
    - User sees countdown: "Rate locked for 18:42"
    - This protects both user and platform from rate swings during payment

SECTION 6 — HOW MONEY FLOWS (OWNER CONTROL ARCHITECTURE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  USER DEPOSITS                                                          │
  │  User sends crypto → NOWPayments detects it on-chain                   │
  │  → Webhook fires → MongoDB Transaction.status = 'completed'            │
  │  → Virtual wallet balance increases                                     │
  │  → Your NOWPayments wallet receives the actual crypto                  │
  │  → You are the custodian of all user funds                             │
  └─────────────────────────────────────────────────────────────────────────┘
                    │
                    ▼
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  SERVICE BOOKING (Escrow)                                               │
  │  Client creates escrow → Deducted from virtual balance                 │
  │  Money stays in YOUR crypto wallet — MongoDB just tracks the obligation │
  └─────────────────────────────────────────────────────────────────────────┘
                    │
                    ▼
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  SERVICE COMPLETION (Provider enters PIN)                               │
  │  EscrowManager.releaseEscrow() is called                               │
  │                                                                         │
  │  NEW: Before release, deduct platform fee:                             │
  │    platformCut  = amount × PLATFORM_FEE_PERCENT (e.g., 10%)           │
  │    providerPays = amount - platformCut                                  │
  │                                                                         │
  │  Transaction { type: 'platform_revenue', amount: platformCut }         │
  │  Transaction { type: 'earning', amount: providerPays, provider_id }    │
  │  → Provider virtual balance increases by providerPays                  │
  │  → Platform virtual balance increases by platformCut                   │
  └─────────────────────────────────────────────────────────────────────────┘
                    │
                    ▼
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  PROVIDER WITHDRAWAL                                                    │
  │  Provider goes to Wallet → clicks Withdraw                             │
  │  Enters their crypto wallet address + chooses currency                  │
  │  POST /api/payments/withdraw                                            │
  │    → Validates virtual balance >= requested amount                     │
  │    → Creates withdrawal Transaction { status: 'pending' }             │

  Service transaction:  PLATFORM_FEE_PERCENT (default 10%)
  Subscription fee:     No platform cut (subscription is pure platform revenue)
  Deposit:              No cut (users top up wallets)
  Withdrawal:           Small flat fee in crypto (e.g., 1 USDT) to cover gas

  Fee deduction happens in: EscrowManager.releaseEscrow()
  Fee recorded as:          Transaction { type: 'platform_revenue' }
  Fee currency:             Same as the escrow transaction's currency
  Fee visibility to owner:  GET /api/admin/revenue
